# Автооператор: факты, диалог и источники

Изменения поверх `feat/autonomous-ai-operator-stage2-replay`, исходный commit `5635777`.

## Рабочий путь

Test Lab и HelpCrunch shadow используют `runFactTurn`. Исторический Replay использует тот же движок с `replay: true`: возвращает необходимую проверку и никогда не читает текущие CRM-данные для исторического обращения. Исходящие сообщения HelpCrunch и CRM WRITE остаются выключены.

1. `interpretOperatorTurn` разбирает реплику в несколько вопросов: сущность, отношение, период, идентификаторы, действие речи. У NLU нет инструментов и возможности записать финансовый факт.
2. `dialogue-state.js` хранит тему, язык, ожидающего кандидата и подтверждённый договор. Однозначные подтверждения и короткие продолжения обходятся без LLM. Login и договор не взаимозаменяемы.
3. `fact-catalog.js` описывает типы, источник и актуальность полей; `FACT_RECIPES` задаёт необходимые факты. `fact-runtime.js` получает только недостающее и группирует чтения одного источника.
4. Финансовые правила исполняются в целых копейках. Derived facts сохраняют договор, конкретный период, входные версии, версию правила и срок актуальности.
5. Ответ собирается из проверенных результатов обычными русскими/украинскими предложениями. Свободный текст NLU не попадает в ответ. Поэтому модель не может добавить выдуманную сумму, обещание передачи или причину неисправности. Это сознательно ограниченный renderer; свободное LLM-перефразирование пока не подключено.

## Что можно дополнять

- Подтверждённое поле: extractor → `FACT_CATALOG` (тип, источник, TTL) → recipe. Пустая строка допустима только там, где её значение определено, например отсутствие следующего тарифа; отсутствие самого поля остаётся UNKNOWN.
- Новое вычисление: чистая функция с явными предусловиями и проверкой границ, затем replay-тест. Название инструмента не зависит от фразы клиента.
- Новая внешняя система: отдельный READ-адаптер с исходным временем наблюдения. Wrapper-время выполнения не обновляет возраст закэшированного значения.
- Статусы: добавлять только после подтверждения конкретного сочетания полей SIMNET. Отрицательный startDay сам по себе не означает удалённый договор или ожидающую активацию.
- Значения и цены: только подтверждённые поля/правила. Цена будущего тарифа не извлекается из цифр в его названии.

TTL сейчас — настраиваемые консервативные значения политики: Billing 120 секунд, сессия 45 секунд, ONU 60 секунд. Это не утверждение о скорости обновления внешних систем. Переход месяца Europe/Kyiv, смена договора и сообщение клиента об изменении требуют пересмотра данных. Неполный результат или ошибка источника удерживаются 30 секунд от автоматического повтора; явное обновление снимает это ограничение. На ход не более шести источников/identity-операций, идентичная операция выполняется один раз.

Snapshot merge сохраняет возраст каждого финансового/служебного поля. Открытие техданных не делает старый баланс свежим. Неуспешное обновление не возвращает старую сумму как новую.

## Совместимость

Старые `routeBasicCase`, `calculateFuturePayment`, `guardFuturePaymentDecision` и `planAutonomousTurn` оставлены для существующих контрактов и тестов. Test Lab, shadow и Replay больше не используют их финансовую маршрутизацию. Старый fallback `accountBalance` сохранён только в legacy API: новый рабочий путь никогда не заменяет им неизвестный остаток после текущего месяца. Старые тесты не удалены и assertions не ослаблены.

## Ограничения

- Поддержаны баланс, текущая ежемесячная сумма, будущая сумма/пополнение, покрытие текущего месяца, тариф, дата списания при явном факте, доступная история, номер договора, оплата, статический IP, административная фаза диагностики и ограниченные сетевые READ.
- Общие неизвестные вопросы требуют уточнения; это ещё не полная матрица L1. Сетевой ответ показывает подтверждённые состояния и уточняет масштаб проблемы, не объявляет неисправный роутер или аварию без данных.
- Для деактивированного договора сумма восстановления не вычисляется без выбранного тарифа и правил активации.
- Будущий тариф рассчитывается только при наличии `nextTariffPrice` и стоимости активных услуг. Источник этой цены не выдуман: без поля ответ сообщает пробел.
- Финансовые расчёты требуют подтверждённого рабочего состояния услуги. Неопределённое состояние не превращается в обещание оплаченного/работающего интернета.
- Исторический Replay без исторических CRM-фактов не может проверить фактическую сумму. Для проверки расчётов используются fixtures в автоматических тестах.
- Реальный Groq и авторизованный Billing в этой среде не опрашивались; проверены функции и интеграция Test Lab на контролируемых ответах транспорта.

## Проверка

`npm run test:ai-operator` — существующие и новые проверки автооператора.

`npm test` — весь прежний regression suite и новые сценарии, без skip и удаления тестов.

Результат проверки: автооператор 50/50 PASS. Исходная ветка: 362 проверки, 287 PASS, 75 FAIL. После изменений: 400 проверок, 325 PASS, 75 FAIL. Списки исходных и итоговых FAIL сопоставлены по именам: новых падений нет, исходные 75 сохранены. Проверка синтаксиса и git diff --check пройдены. Общий CI не считается зелёным, пока исходные проблемы не устранены.

## Расход API и светлая страница

В Test Lab видны оценка стоимости последнего хода, диалога и итог автооператора с начала учёта. Учёт находится на уровне каждого HTTP-вызова модели: успешный ответ, ответ с неверным JSON и fallback считаются отдельно. Ходы без LLM стоят 0 в счётчике. Токены берутся из usage провайдера; ошибки/таймауты без usage отмечаются как неизвестная часть, а не бесплатные вызовы. Суммы не исчезают при обрезке истории или создании нового диалога. Это не баланс аккаунта Groq и не расходы других модулей/устройств.

Начальные ставки USD за миллион токенов проверены 2026-09-16 по https://console.groq.com/docs/models : Qwen 3.6 — 0.60/3.00, Qwen 3.8 — 0.80/4.00, GPT-OSS 120B — 0.15/0.60, GPT-OSS 20B — 0.075/0.30 (вход/выход). Кэш GPT-OSS: 0.075 и 0.037 соответственно, по страницам моделей Groq. Неизвестная цена кэша заменяется обычной входной ставкой с явной пометкой оценки. Ставки редактируются в блоке «Изменить цены моделей»; прошлые токены переоцениваются по выбранным ставкам. Это расчётная стоимость по стандартному тарифу, без учёта бесплатной квоты и индивидуальных скидок. Денежного лимита/остановки запросов нет.

Светлое оформление применяется ко всей settings.html, в том числе формам, чату, логам, Replay и карточкам. Цвет основных кнопок SIMNET сохранён.

Визуальный browser smoke-test не выполнен: Chromium отсутствовал, загрузка завершилась сетевыми ошибками. Синтаксис UI проверен; расположение блоков требует просмотра в установленном расширении.
